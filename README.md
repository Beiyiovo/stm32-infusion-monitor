# 基于单片机的输液状态 WiFi 监测装置

> 毕业设计 · 电子工程学院 · 物联网工程
> 状态：**进行中**（2026-10-21 开工，硬件未到货，代码完成第 1 段）

用 STM32 采集输液液体的**温度**与**剩余重量**，OLED 实时显示，超阈值时蜂鸣器 + LED 分级报警，
再通过 WiFi 把数据送到手机上查看。

## 二、硬件构成

| 器件 | 型号 / 规格 | 作用 | 备注 |
|---|---|---|---|
| 主控 | STM32F103C8T6 最小系统板 | 采集、显示、报警、数据打包 | 蓝板，**无板载 CH340** |
| 无线 | ESP32-C3 核心板（CORE-ESP32，4MB） | WiFi + TCP Server | 烧 AT 固件 V4.1.1.0 |
| 温度 | DS18B20 防水探头 | 液体温度 | 精度规格本身 ±0.5℃ |
| 称重 | 1kg 悬臂梁 + HX711 | 剩余药量 | 0.05%FS 估算 ≈ 0.5g |
| 滴速 | 红外对射（分体式）+ 遮光罩 | 数滴/分钟 | 夹滴壶两侧；槽型光耦装不上 |
| 显示 | 0.96 寸 OLED，I2C，4 针 | 人机界面 | 需 4.7kΩ 上拉 |
| 报警 | 有源蜂鸣器模块 + 红/黄 LED | 分级报警 | 蜂鸣器 VCC 必须 3.3V |
| 输入 | 轻触按键 6×6×5 ×4 | 设置/加/减/确认 | 内部上拉，另一端接 GND |

引脚分配与逐脚接线见 [`文档/502引脚分配与逐脚连线表.docx`](文档/)。

## 四、快速开始

### 编译

```powershell
代码\build.bat 01_uart
```

需要 Keil MDK 5.42（ARMCLANG V6.23）。产物：`代码\01_uart\Objects\502_01_uart.bin`。
> 本工程实测可在**含中文的路径**下编译（0 Error 0 Warning）。

### 烧录

蓝板无板载 CH340，只能串口 ISP：

1. USB-TTL 接 `TXD→PA10`、`RXD→PA9`、`GND→GND`
2. BOOT0 拨到 **1**，复位
3. 烧 `502_01_uart.bin`，**波特率 9600**（115200 实测从未成功）
4. 烧完 BOOT0 拨回 **0**，复位
5. 串口助手 115200 8N1 看打印

### 接线

按 `文档/502引脚分配与逐脚连线表.docx` 的「逐脚连线表」接，
接之前先过一遍「12 条硬约束」——尤其 I2C 上拉、蜂鸣器 3.3V、ESP32 独立供电。

## 五、设计决策（为什么这么做）

| 决策 | 选择 | 理由 |
|---|---|---|
| 主控方案 | STM32 + ESP32（AT 固件），不用 ESP32 单主控 | 可复用上一项目（个人健康助手）已验证的驱动框架；ESP32 不必重烧固件 |
| 数据怎么走 | ESP32 做 TCP Server，手机与它同一热点，安卓 App 直连 | 不依赖外网，答辩现场稳；上报层已隔离成单独文件，需要时整体换 MQTT |
| 称重量程 | 1kg（非 5kg） | 按 500ml 袋设计；0.05%FS 下 1kg≈0.5g、5kg≈2.5g，后者会吃掉整个 ±2g 余量 |
| 滴速传感器 | 红外对射（分体式） | 滴壶直径约 20mm，槽型光耦（约 5mm 槽）卡不进去，必须让光路横穿壶体 |
| 报警分级 | 黄灯预警 / 红灯+蜂鸣 | 课题任务书要求"分级报警" |

## 六、已知限制（诚实清单）

- **局域网直连 ≠ 云平台**：手机必须与 ESP32 在同一热点，离开就看不到；若验收按字面要求"上传平台"，需切 MQTT
- **现场 WiFi 有坑**：校园网要 Portal 认证，ESP32 过不去 → 演示要用手机热点或实验室路由器
- `01_uart` **只编译通过，没有在真实板子上烧过**
- 称重 ±2g、温度 ±0.5℃、滴速 ±3 滴/min **均无实测数据**
- 滴速在"液滴成线"时数不到 —— 光学方法的原理性局限，不是 bug
